
# FlyweightCinema

Навчальний проєкт на Ruby, який демонструє застосування
структурного патерна проєктування «Легковаговик» (Flyweight)
на прикладі системи керування місцями в кінотеатрі.

## Опис проєкту

Програма моделює кінотеатр із 5 залами.
У кожному залі є 10 рядів по 20 місць.

Загалом створюється 1000 місць трьох категорій:
- Standard
- Comfort
- VIP

Кожне місце має власний номер залу, ряду, місця
та незалежний статус бронювання.

Характеристики категорій крісел (матеріал, ширина,
простір для ніг, регулювання спинки, опис) зберігаються
у спільних об'єктах SeatType.

Завдяки патерну Flyweight для 1000 місць
використовуються лише 3 об'єкти SeatType.

## Структура проєкту

- `seat_type.rb` - клас легковаговика, що зберігає
  спільні незмінні характеристики крісла.
- `seat_type_factory.rb` - фабрика, яка кешує
  та повторно використовує об'єкти SeatType.
- `seat.rb` - конкретне місце з індивідуальними
  координатами та статусом бронювання.
- `cinema.rb` - створення місць, пошук і бронювання.
- `main.rb` - демонстрація роботи програми.
- `memory_comparison.rb` - порівняння використання
  пам'яті з Flyweight і без нього.

## Як запустити



Перейдіть у папку проєкту та виконайте:

```bash
ruby main.rb
```

Для запуску експерименту з пам'яттю:

```bash
ruby memory_comparison.rb
```

## Результати експерименту

Для 1000 місць було отримано такі результати:

| Показник | Значення |
|---|---:|
| Кількість місць | 1000 |
| Кількість спільних типів | 3 |
| Без Flyweight | 416 000 байтів |
| З Flyweight | 1 040 байтів |
| Економія | 414 960 байтів |
| Відносна економія | 99,75% |

Вимірювання виконано за допомогою стандартної
бібліотеки Ruby `objspace`.

Порівнюється пам'ять структур, що зберігають
характеристики крісел, а не загальне споживання
оперативної пам'яті всім застосунком.

## Висновок

Патерн «Легковаговик» дозволяє зменшити дублювання
однакових даних завдяки спільному використанню
незмінних об'єктів.

У цьому проєкті 1000 окремих місць використовують
лише 3 об'єкти з характеристиками категорій крісел.
